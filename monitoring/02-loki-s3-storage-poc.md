# Loki 중앙집중형 로깅 S3 오브젝트 스토리지 전환 PoC

> 본 문서는 **진행 중인 PoC**를 다룹니다. 일부 항목은 완료, 일부는 검증·검토 단계입니다.

## 1. 배경

### 가. 기존 문제

1) ELK Stack과 Loki가 로그를 이중으로 저장하며 스토리지 중복 사용이 발생 — Loki 중심으로 단일화할 필요
2) NFS 기반 로그 장기보관 스토리지 사용량이 최근 반년 사이 약 2TB씩 꾸준히 증가하는 추세
3) NFS 스토리지는 용량 확장 시 비용 부담이 크며, CSAP 인증 운영 환경에서는 NFS보다 S3(오브젝트 스토리지) 비용이 더 저렴해 전환을 검토

## 2. 진행 현황 및 확인된 사실

### 가. AS-IS / 검토·PoC 결과

| 항목 | AS-IS | PoC 진행 결과 |
|---|---|---|
| 로그 저장 | ELK + Loki 이중 저장 | Loki 단일화 + S3 백엔드 연동 설정 완료 |
| 보존 정책 | 미설정 | Loki 자체 보존 28일로 설정, 장기보관은 별도 백업 체계에 위임 |
| S3 연동 검증 | 미검증 | 업로드 시 체크섬 프로토콜 호환성 문제 발견, 근본 원인 규명 완료 |
| 최신 버전 운영 | - | 현재 조합으로는 CSAP 최신 버전 유지 요건 충족 불가 — 후속 조치 필요 |

### 나. 발견한 기술적 제약

1) 최신 Loki 버전이 사용하는 S3 스트리밍 체크섬 업로드 방식을, 사내 S3 호환 오브젝트 스토리지 장비가 지원하지 않아 객체 쓰기가 실패하는 현상을 재현·원인 규명
2) 장비 담당자와 로그를 공동 분석해 스토리지 장비가 신규 체크섬 프로토콜 자체를 해석하지 못하는 것을 확인 — 장비 펌웨어 업그레이드 등 벤더 측 대응이 필요한 사안으로 파악

## 3. 예정

1) 로그 저장용 버킷을 데이터 버킷과 분리 요청
2) Loki 신규 버전에서 대응 설정이 추가되는지 지속 확인
3) 오브젝트 스토리지 장비의 펌웨어 업그레이드 일정 및 신규 프로토콜 지원 여부 확인
