# 로그 수집 에이전트 Promtail → Alloy 마이그레이션

## 1. 배경

### 가. 목적

1) 기존 로그 수집 에이전트(Promtail)의 EOL(지원 종료)에 따라 대체 에이전트인 Grafana Alloy로 마이그레이션

## 2. 기대효과

### 가. EOL 리스크 해소

1) 지원 종료 예정인 에이전트를 공식 대체 에이전트로 교체해 향후 보안 패치·버그 픽스 공백 없이 운영 지속

### 나. 인덱스 최적화

1) 마이그레이션 과정에서 Loki 인덱스 최적화를 위한 최소 label 수집 설계를 함께 적용

### 다. AS-IS / TO-BE 비교

| 항목 | AS-IS | TO-BE |
|---|---|---|
| 로그 수집 에이전트 | Promtail (EOL) | Grafana Alloy |
| 설정 마이그레이션 | 수동 재작성 | 공식 변환 툴(`alloy convert`) 활용 |
| 레이블 수집 | 검토 전 | Loki 인덱스 최적화 위한 최소 label만 수집 |
| 검증 | - | Stage 환경에서 로그 누락/중복, 리소스 사용량 검증 후 프로덕션 반영 |

## 3. 구성도 (마이그레이션 흐름)

```
STEP 1  alloy convert로 Promtail 설정 → Alloy 설정 변환
  │
  ▼
STEP 2  Offset 저장 경로(hostPath), relabel 규칙(동적 변수 할당) 등 세부 설정 조정
  │
  ▼
STEP 3  Stage 배포 — 특정 레이블 기반 로그 조회 오류 발견 및 relabel 규칙 수정
  │
  ▼
STEP 4  로그 누락/중복 여부, 리소스 사용량 검증
  │
  ▼
STEP 5  프로덕션 반영 완료
```

## 4. 성과

1) EOL 에이전트를 대체 에이전트로 전환해 지원 종료에 따른 운영 리스크 해소
2) 마이그레이션 과정에서 발견한 relabel 규칙 오류를 Stage 단계에서 사전에 수정해 로그 조회 기능 정상화
3) 최소 label 수집 설계로 Loki 인덱스를 최적화하고, 검증까지 마친 뒤 프로덕션 반영 완료
