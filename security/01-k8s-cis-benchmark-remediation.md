# CSAP 인증 대응 Kubernetes 보안 취약점 전수 진단 및 조치

TA Unit

## 1. 배경

### 가. 요구사항

1) CSAP(클라우드 보안 인증) 인증 항목 중 컨테이너 접근 통제, 사용자 식별 및 권한 설정을
   충족해야 했는데, 해당 항목 상당수가 Kubernetes 기본 컴포넌트만으로는 지원되지 않아
   third-party 오픈소스 검토를 포함한 전수 진단·조치가 필요했음
2) 약 2개월간 기획(현황 파악, 오픈소스 검토·테스트, 조치)과 이행(QC, 가이드·결과 보고서
   작성)을 단독으로 수행

## 2. 기대효과

### 가. 표준 기반 전수 진단으로 누락 없는 대응

1) kube-bench + CIS Benchmark라는 검증된 기준으로 control-plane, etcd, worker node,
   Kubernetes Policies 전 영역을 점검해, 인증 심사 시 근거를 갖춘 대응 가능

### 나. 오픈소스 도입을 통한 기본 컴포넌트 한계 극복

1) Kubernetes 기본 기능만으로는 지원되지 않는 세부 RBAC/Pod 보안 정책을 Kyverno 도입으로
   보강, 인프라 컴포넌트별 예외 처리 근거까지 함께 문서화

### 다. 리스크 기반 의사결정 문서화

1) 모든 미조치 항목을 "조치 가능 여부"와 "미조치 사유"로 구분해, 단순 체크리스트 이행이
   아닌 서비스 영향을 고려한 판단 근거를 남김

### 라. 조치 현황 요약

| 구분 | 점검 항목 | 즉시조치 | 중기조치(오픈소스 도입) |
|---|---|---|---|
| control-plane | 76개 | 23건 완료 | - |
| etcd | 7개 | 해당 없음 | - |
| worker node | 23개 | 5건 완료 | - |
| Kubernetes Policies (RBAC/PSP) | 35개 | 2건 완료 | 27/28건 완료 (Kyverno) |

## 3. 구성도 (조치 프로세스)

```
STEP 1  kube-bench + CIS Benchmark 기반 전수 진단 (141개 항목)
  │
  ▼
STEP 2  즉시조치 — kubespray 파라미터 변경 (audit 로깅, 암호화, cipher suite 등)
  │
  ▼
STEP 3  오픈소스 도입 검토 — Kyverno 선정, RBAC/PSP 정책 설계 및 예외 처리
  │
  ▼
STEP 4  리스크 평가 — TLS/Token 관리 등 서비스 영향 큰 항목은 근거 기반 의도적 미조치
  │
  ▼
STEP 5  QC 검증 — 1노드 → 3노드 순차 적용, 이슈 대응
  │
  ▼
STEP 6  CSAP 증적 제출용 가이드·결과 보고서 작성
```

## 4. 성과

1) 총 141개 점검 항목 중 즉시조치 30건, Kyverno 기반 중기조치 27건을 완료해 CSAP 인증
   항목(컨테이너 접근 통제, 사용자 식별 및 권한 설정)을 충족
2) 미조치 항목은 모두 근거와 함께 문서화해, 서비스 영향을 고려한 리스크 기반 의사결정
   과정을 남김
3) 신규 클러스터 구축 시에도 적용 가능한 표준 보안 가이드로 반영
