# CSAP 인증 대응 Kubernetes 보안 취약점 전수 진단 및 조치

## 1. 배경

### 가. 요구사항

1) CSAP(클라우드 보안 인증) 인증 항목 중 컨테이너 접근 통제, 사용자 식별 및 권한 설정을
   충족해야 했는데, 해당 항목 상당수가 Kubernetes 기본 컴포넌트만으로는 지원되지 않아
   third-party 오픈소스 검토를 포함한 전수 진단·조치가 필요했음
2) 약 2개월 동안 진행, 본인이 기획(현황 파악, 오픈소스 검토·테스트, 조치)과 이행(QC, 가이드·
   결과 보고서 작성)을 단독으로 수행

## 2. 기대효과

### 가. 체크리스트 이행을 넘어선 리스크 기반 의사결정

1) 조치 가능한 항목도 서비스 영향을 검토해 "즉시조치/중기조치/의도적 미조치"로 구분하고,
   미조치 항목까지 근거와 재검토 조건을 문서화해 단순 형식적 인증 대응이 아닌 실질적인
   보안 수준 판단 과정을 남김

### 나. 표준 보안 가이드로의 확장

1) 이번 진단·조치 결과를 신규 클러스터 구축 시에도 적용 가능한 표준 보안 가이드로 반영해,
   1회성 인증 대응이 아니라 재사용 가능한 자산으로 전환

### 다. AS-IS / TO-BE 비교

| 항목 | AS-IS | TO-BE |
|---|---|---|
| 점검 범위 | 미실시 | kube-bench + CIS Benchmark 기준 141개 항목(control-plane 76, etcd 7, worker 23, Policies 35) 전수 점검 |
| 즉시 조치 가능 항목 | 미조치 | kubespray 파라미터 조정만으로 30건 조치(인증서 권한, audit 로깅, secret 암호화 등) |
| RBAC/PSP 세부 정책 | Kubernetes 기본 컴포넌트로 미지원 | Kyverno 오픈소스 도입, 28건 중 27건 정책 기반 조치 |
| 조치 곤란 항목 | 방치 | 서비스 영향 근거와 함께 "의도적 미조치"로 문서화, 재검토 조건 명시 |

## 3. 조치 흐름

```
STEP 1  kube-bench + CIS Benchmark 기준 141개 항목 전수 점검
  │
  ▼
STEP 2  kubespray 파라미터 조정만으로 해결 가능한 30건 즉시조치
  │
  ▼
STEP 3  Kyverno 도입 검토·선정 → RBAC/PSP 정책 27건 조치, 인프라 컴포넌트 예외는
        사유와 함께 문서화
  │
  ▼
STEP 4  TLS/Token 관리 등 리스크 대비 조치 이익이 낮은 항목은 근거와 함께 의도적 미조치로 결정
  │
  ▼
STEP 5  1노드 환경 선적용 → 정책 충돌 시행착오 확인 → 3노드로 확장, QA와 11개 항목 회귀 테스트
  │
  ▼
STEP 6  CSAP 심사 제출용 조치 가이드·결과 보고서 작성
```

## 4. 성과

1) 총 141개 점검 항목 중 즉시조치 30건, Kyverno 기반 중기조치 27건을 완료해 CSAP 인증 항목을 충족
2) 미조치 항목도 모두 근거와 함께 문서화해, 체크리스트 이행이 아닌 리스크 기반 의사결정 과정을 남김
3) 신규 클러스터 구축 시에도 적용 가능한 표준 보안 가이드로 반영
