# CSAP 인증 유지·갱신 대응 유지보수 자동화

## 1. 배경

### 가. 요구사항

1) CSAP 인증은 최초 취득으로 끝나지 않고, 유지·갱신 심사를 위해 계정 관리, 시각동기화,
   취약점 재점검, 재해복구(DR) 검증 같은 반복 업무를 지속적으로 수행해야 함
2) 1차로 본인이 작업별 Ansible playbook을 개별적으로 직접 개발해 반복 업무 자체는
   자동화했으나, playbook마다 실행 방식이 제각각이고 공통 설정 파일도 없어 본인이 아니면
   유지보수하기 어렵다는 한계가 있었음
3) 이를 인식해 2차로, 본인이 아니어도 다른 담당자가 유지보수할 수 있도록 단일
   entrypoint(wrapper) 기반의 공통 실행 프레임워크를 추가로 설계

## 2. 기대효과

### 가. 반복 업무의 단일 진입점 표준화

1) 주기(일간/분기/연간) → 작업 선택의 2단계 메뉴로 모든 유지보수 playbook을 통합해,
   운영자가 개별 명령어를 암기할 필요 없이 반복 업무를 수행할 수 있도록 개선

### 나. 인증 심사 증적 자료의 상시 확보

1) 계정 생명주기, 시각동기화, 취약점 재점검, DR 검증까지 CSAP 유지·갱신 심사에 필요한
   반복 증적을 자동으로 생성할 수 있는 체계를 구축해 현재도 운영 중

### 다. AS-IS / TO-BE 비교

| 항목 | AS-IS (1차, 본인 개발) | TO-BE (2차, 본인 개발) |
|---|---|---|
| 실행 방식 | playbook마다 제각각, 개별 명령어 암기 필요, 본인 외 유지보수 어려움 | 단일 entrypoint(`maint-wrapper.sh`)의 2단계 메뉴로 통합, 인수인계 가능한 형태로 표준화 |
| 계정 관리 | 수동 생성·삭제 | 일간 자동화(생성/초기화/퇴사자 삭제), 분기별 CSV 기준 적정성 검토 자동화 |
| 시각동기화 점검 | 수동 확인 | Linux/Windows 동일 포맷으로 자동 점검 |
| 취약점/DR 검증 | 비정기 수동 실시 | 연간 주기 스크립트로 관리 |
| 변경 검증 | 실제 환경에서 직접 확인 | 더미 계정 기반 회귀 테스트 + teardown으로 운영 환경 영향 없이 검증 |

## 3. 조치 흐름

```
STEP 1  제각각이던 유지보수 playbook을 단일 entrypoint(maint-wrapper.sh)로 통합
  │
  ▼
STEP 2  주기별(일간/분기/연간) 자동화 범위 설계 — 계정/시각동기화/취약점·DR
  │
  ▼
STEP 3  안전장치 적용 — 비밀번호 미노출, --check 모의 실행, 계정별 고유 초기 비밀번호
  │
  ▼
STEP 4  더미 계정(csaptest_ 접두사) 기반 회귀 테스트 체계 구축, teardown으로 원상복구
```

## 4. 성과

1) 유지보수 playbook 실행 방식을 단일 entrypoint로 표준화해 반복 업무 수행 부담 축소
2) CSAP 유지·갱신 심사에 필요한 반복 증적 자료를 자동 생성하는 체계를 구축해 현재도 운영 중
3) 실제 계정을 다루는 자동화임에도 더미 계정 기반 회귀 테스트로 운영 환경에 영향 없이 검증 가능
