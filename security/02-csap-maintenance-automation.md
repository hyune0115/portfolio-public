# CSAP 인증 유지·갱신 대응 유지보수 자동화

TA Unit

## 1. 배경

### 가. 요구사항

1) CSAP 인증은 최초 취득으로 끝나지 않고, 유지·갱신 심사를 위해 계정 관리, 시각동기화,
   취약점 재점검, 재해복구(DR) 검증 같은 반복 업무를 지속적으로 수행해야 함
2) 기존에는 유지보수 Ansible playbook이 있었지만 playbook마다 실행 방식이 제각각이고
   공통 설정 파일도 정리되어 있지 않아, 운영자가 개별 명령어를 직접 기억해야 하는 문제가
   있었음

## 2. 기대효과

### 가. 단일 진입점으로 운영 부담 감소

1) 모든 유지보수 작업을 하나의 대화형 메뉴로 통합해, 운영자가 개별 명령어를 암기할 필요
   없이 반복 업무를 수행할 수 있도록 개선

### 나. 인증 갱신 심사 대응력 확보

1) 계정 생명주기·시각동기화·취약점 재점검·DR 검증까지 CSAP 유지·갱신 심사에 필요한 반복
   증적 자료를 자동으로 생성할 수 있는 체계를 구축해 현재도 운영 중

### 다. 변경에 안전한 자동화

1) 더미 계정과 일회용 대상 서버로만 검증하는 회귀 테스트 체계를 도입해, 실제 계정을
   다루는 자동화임에도 운영 환경에 영향 없이 변경 사항을 검증

### 라. AS-IS / TO-BE 비교

| 항목 | AS-IS | TO-BE |
|---|---|---|
| 실행 방식 | playbook마다 실행 방식이 제각각, 공통 설정 부재 | 단일 entrypoint(대화형 메뉴)로 통합 |
| 대상 관리 | 정적 inventory 필요 | 실행 시점 동적 host 구성 |
| 계정 적정성 검토 | 수동 확인 | CSV 업로드 기반 자동 감지·정리 |
| 변경 검증 | 없음 | 정적 검사 + 더미 계정 기반 회귀 테스트 |

## 3. 구성도 (유지보수 주기)

```
운영자 → 단일 entrypoint (대화형 메뉴)
  │
  ├─ 일간   : 계정 생성/삭제/비밀번호 초기화/만료 관리, 관리자 비밀번호 주기 갱신(cron)
  │
  ├─ 분기   : 계정 적정성 검토(CSV 기반 자동 정리), 시각동기화 점검
  │
  └─ 연간   : CCE 취약점 점검, DR 복구 검증 (별도 실행)
```

## 4. 성과

1) 제각각이던 유지보수 playbook 실행 방식을 단일 entrypoint로 표준화
2) CSAP 유지·갱신 심사에 필요한 반복 증적 자료 생성 체계를 구축해 현재도 운영 중
3) 더미 계정 기반 회귀 테스트로, 운영 환경에 영향 없이 변경 사항을 검증할 수 있는 안전장치
   확보
